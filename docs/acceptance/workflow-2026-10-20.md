## Automated acceptance

`pnpm run check` passed **477 tests in 72 suites**. Full hidden `pnpm run e2e` passed **131 tests in 36 suites** in 406 seconds, including the four new I3 scenarios. No product code, public protocol, persistence format or vendored Pi code changed.

The real Desktop, Host, Tool Router and executor use isolated data and Keychain services. A TLS CRM fixture maintains its own account versions and effect ledger. A search fixture supplies a lead; the complete synthetic policy capture is read from the workspace. A real approved Node command joins current CRM data with invoice rows and writes the report. Assertions inspect JSON/file bytes, immutable artifact previews, exact approval arguments, routine skill digests, occurrence reports and the independent remote ledger.

The suite exercises 21 decision/confirmation points: 6 for the first scenario, 7 for reuse/recovery, 6 for the two failure scenarios and 2 for response loss. These are automated approvals, denial, correction, routine confirmation/test and explicit reconnect points; initial setup and ordinary task prompts are excluded. They are not a measurement of human time. Observed connector retry requests: **0**; unapproved effects: **0**; duplicate confirmed effects: **0**. The deliberately uncertain third effect is recorded separately from the two confirmed updates.

Scripted model usage totals **4,680 synthetic tokens**; prices are unavailable. These controlled counts test accounting, not model efficiency. Each run writes measured per-scenario durations, outcomes, interventions, call/effect counts, usage and its candidate SHA to ignored `e2e/.run/workflow-acceptance/evidence.json`. Reproduce with:

## Real-model spot check

A configured remote model completed one bounded synthetic sequence using the same CRM fixture and calculator. Credentials and provider configuration stayed in isolated state and are excluded from this record.

| Stage | Elapsed | Independent verification |
| --- | --- | --- |
| Source review, report and approved update | 58.1 s | JSON total $2,000 / overdue $1,200; immutable artifact; exactly one Atlas update. |
| Reviewed reusable procedure | 35.9 s | Model proposed `receivables-review`; exact approval saved revision 1 with source checks, record versions and approval/unknown-result boundaries. |
| Routine with changed invoices | 69.4 s | Exact skill pin; JSON total/overdue $2,500; one Boreal update; model read back CRM state. |

Including setup/relaunch, the sequence took **166.7 seconds**, exercised **11 approval/confirmation points**, reported **330,269 tokens**, and had no configured price estimate. The CRM received four reads and two writes; both writes occurred once. Restart retained the earlier $1,200 report, the new $2,500 report and exactly one routine publication. This small successful trial is not a quality, latency or cost benchmark.

The model attempted `web_fetch` on the public IANA example-domain reference once. It returned `Fetch failed: fetch failed`; **live public retrieval was not verified**. The model reported the limitation and used the complete local synthetic policy capture for the calculation. Neither the fabricated search lead nor its attributed example URL is claimed as an independently verified live policy page. Production loopback/private-address protection was not changed.
