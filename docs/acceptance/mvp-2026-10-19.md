The new [`mvp-acceptance.e2e.ts`](../../e2e/mvp-acceptance.e2e.ts) drives the actual hidden Electron app, Host and executor. A ScriptedModel chooses tools, while a real Node process computes the committed [synthetic CSV](../../examples/weekly-sales.csv). Assertions independently check totals, product deltas and exported bytes. The test proves no calculation before approval, a separate denied command creates no file, a published copy survives source deletion/restart, and restart does not repeat the calculation. Native save dialogs are stubbed to an isolated destination.

Existing suites cover onboarding, read-only commands, Always allow, approval durability, queue/Stop, background completion, memory, search, lifecycle/observation recovery, artifacts, skills, groups and both connector transports. They use isolated data/workspaces/Keychain services, hidden non-focusable windows and suppressed native attention effects.

## Real-provider work

Provider class: configured OpenAI-compatible gateway, model `gpt-6.1-sol`. The application used its normal credential broker with an isolated Keychain service. Input data and Bot identities were synthetic. No owner workspace or conversation data was opened.

The first successful four-scenario run recorded **94,089 tokens** and verified:

- The Core saved the preference “USD, week-over-week comparison, one actionable next step” through its memory tool.
- One exact `node denied-action.mjs` approval was denied. The sentinel output file did not exist, including after restart.
- One exact `node analyze-sales.mjs` approval was allowed. The actual calculation ran once; the independent counter stayed at one after restart.
- Twelve input rows produced $12,000 in the prior week and $13,400 in the current week: +$1,400, or 11.6667%. Orbit contributed +$1,400, Beacon +$400 and Relay −$400.
- The Bot wrote a Markdown brief and published it with the CSV. Both immutable artifacts matched the actual files; both remained readable after restart and removal of the Markdown source.
- After a full application restart and a new topic, the Core recalled the saved preference. Temporary model credentials were deleted; transcript and local diagnostics checks found no credential value.

This run exposed ambiguous artifact-name guidance: the model first supplied titles without extensions, received format errors and then correctly retried with filenames. The parameter description now states that `name` is a filename retaining the supported extension, or may be omitted. No schema validation, file-format rule or approval contract changed.

A subsequent real-provider run saved the calculation and Markdown, then returned `invalid_request_error` before publication. The application reported a failed Run and retained prior effects. Recovery uses an explicit follow-up to finish from existing files, with the calculation counter checked again. Recovery passed on Run `run_759df3c3-88d3-499c-b9e5-7ed00b03b9ca`: the Bot read the existing source and outputs, corrected a currency note, published both files with valid filenames and completed without another command approval or calculation. The counter remained exactly `calculated\n`. A further restart/source-removal check retained both immutable copies, and Run `run_400e813f-c64e-4cd0-b9d1-e63d3587b843` recalled the memory in a new topic. The second isolated session recorded **108,915 tokens** across its initial and recovery work. Both final Bot Runs were independently confirmed `completed`, and the test credential index was empty.

The initial recovery harness accidentally reused a request ID with different text; the Host correctly rejected it with `request_conflict` before dispatch. The follow-up used a fresh request ID. An earlier harness also treated relative `cwd: "."` too strictly; its path assertion was corrected before granting the intended calculation approval. These were test-driver corrections, not product bypasses.

Real-model output varies. These checks establish the observed task results, not a provider reliability benchmark or a guarantee that every request succeeds.
